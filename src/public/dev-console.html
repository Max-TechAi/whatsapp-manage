Quick Start — Common Tasks

Use these two API calls to send WhatsApp messages from your CRM or website. Create your account, link WhatsApp, and get your API key in the dashboard (Team → API Keys) — that setup is browser-only, not shown here.

Authenticate every request with: Authorization: Bearer YOUR_API_KEY (or X-API-Key: YOUR_API_KEY).

POST /api/send-message

Send a text message to one person or to a WhatsApp group. The message is queued and delivered through your linked WhatsApp number.

POST /api/messages is an equivalent alias — same handler, same behavior. 

curl -X POST "https://YOUR_HOST/api/send-message" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "sessionId": "YOUR_SESSION_ID",
    "recipientJid": "966500000000",
    "body": "YOUR_MESSAGE_TEXT"
  }'

recipientJid: for a person, you can use just their phone number (e.g. 966500000000 or +966500000000) OR the full format 966500000000@s.whatsapp.net. For a group, use the group id from the groups list below (it already ends with @g.us).

Example response (202):

{
  "success": true,
  "message": "Message queued for sending",
  "data": {
    "jobId": "sess-...-msg-...",
    "chatId": "uuid-of-chat-thread",
    "waChatJid": "966500000000@s.whatsapp.net"
  }
}
More detail — optional fields & errors

Required body fields: sessionId, recipientJid. For text messages, include body.

Optional fields:

  • messageType — text (default), image, video, audio, document
  • mediaUrl, mediaMimeType, filename — for media messages
  • quotedMessageId — reply to an existing message (internal UUID)
  • forwardMessageId — forward an existing message

Common errors:

  • 401 — missing or invalid API key
  • 403 — your API key’s user lacks access to this session or chat
  • 404 — session not found
  • 429 — rate limit exceeded

GET /api/sessions/:id/groups

List WhatsApp groups on a linked session so you can copy the correct group ID for sending messages.

curl -X GET "https://YOUR_HOST/api/sessions/YOUR_SESSION_ID/groups" \
  -H "Authorization: Bearer YOUR_API_KEY"

Each group’s id field (e.g. 120363123456789012@g.us) is what you pass as recipientJid when sending a message to that group.

Example response (200):

{
  "success": true,
  "data": [
    {
      "id": "120363123456789012@g.us",
      "subject": "Sales Team",
      "participantsCount": 12
    }
  ]
}
More detail — fields & errors

Path parameter: replace :id with your session UUID (find it in Dashboard → Sessions).

Response fields:

  • id — group JID; use as recipientJid when sending (includes @g.us)
  • subject — group display name
  • participantsCount — number of members

Common errors:

  • 401 — missing or invalid API key
  • 404 — session not found or not in your organization
  • 500 — server error fetching groups
